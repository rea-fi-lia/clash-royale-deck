# カード更新の共通経路

2026-09-23 本人指定：新カードだけでなく、進化・限界突破・ヒーロー追加、バランス変更、同一URLの画像差し替えを一度の更新で全体へ反映する。各画面に個別の例外を増やさない。

## 正本と反映先

公開メタデータの正本は `catalogue/cards.json`。日本語内部名・英名・公式ID・slug・コスト・種別・読み・役割・勝ち筋分類と優先順（winConditionPriority）・Wiki取得先・形態別画像とSHA256を管理する。手作業の役割・検索別名はAPI更新で上書きしない。

| 利用先 | 経路 |
|---|---|
| ビルダー・検索・人気デッキ・マイページ | 生成済み `js/cards-data.js` の共通関数 |
| 公式ゲームへのコピー・リンク読込 | 台帳内の公式ID。古いdataブランチのID表を別取得しない |
| 試合収集 | `card-catalogue.cjs` からID/slug→内部名・コストを取得 |
| 詳細の取得 | 毎回台帳全件から取得対象を再構成。既存statsに無いカードも追加 |
| カード個別ページ | 同じ台帳・更新候補statsを入力。名称の結合はslugを優先 |
| OGP・ランキング画像・Workerのカード判定 | 配信済み `catalogue/manifest.json` をWorkerが60秒間隔で再確認 |
| 監修シート | 確認済み形態別数値だけ同期。進化行へ通常値を流用しない |

`js/cards-data.js` は生成物。共通関数は `tools/templates/cards-runtime.js` を編集する。旧 `gas/Code.gs` は移行前の参考資料で本番収集の正本ではない。

## 更新と公開

```sh
# 台帳を編集した後。画像の内容を検証して生成（公開操作は含まない）
node tools/update-card-catalogue.js --images
node tools/update-card-catalogue.js --check
node --test tools/test-card-catalogue.mjs
node tools/check-card-images.js --lint-only
```

既存 `build-card-stats.yml` を統合更新経路にした。毎日13:40 JSTに既存CR_TOKENで公式 `/cards` を照合し、既知カードのID・英名・コスト・既知の追加形態を更新。画像全件のPNG構造と内容ハッシュを検査し、R2現物を土台に詳細の候補を作り、個別ページ・17言語・リンクを検査してから公開する。手動 `dry_run=true` はGit/R2/シート更新も通知送信もしない。レビュー用artifactは公開カード台帳と差分報告だけで、生試合・非公開統計を含めない。

未知のカードは日本語名・種別・役割・Wiki取得先を確認して**台帳1か所**へ追加する。APIだけでは確定できない意味を推測して公開しない。未対応のアイコン種別、公式一覧からの消失、対応していない進化段階は更新を止めて差分に残す。新しい仕組みそのものはレンダラーの対応が必要だが、通常カードとして黙って通さない。

画像内容SHA256がURLの版番号になる。画像URLが変わらなくても内容変更でブラウザーとWorkerの生成画像キャッシュが切り替わる。JS共通関数の変更もscriptの版番号に含む。Worker更新は通常のカード追加には不要。初回通信失敗は同梱台帳、更新失敗は最後に検証できた台帳を利用し、`/api/card-catalogue` と `X-Card-Catalogue` / `X-Card-Catalogue-Source` で稼働版を確認できる。

GitHub PagesとR2は別サービスなので同時切替ではない。両方の生成・検査を先に済ませ、ページ反映後にR2を更新する。R2の元データがビルド中に変わっていれば公開を止める。途中失敗はworkflow失敗として残り、同じ経路を再実行する。画像版はPagesのmanifestに追従するため、新カードのたびにWorkerへ辞書を手コピーしない。

## 数値・形態・バランスの正確さ

- 取得元はコミュニティWikiで、公式APIの戦闘能力値ではない。取得成功日とゲーム内調整の確認日は同一視しない。「翌日必ず最新」の表示を廃止した。
- 各カードに `freshness.status=current/stale/missing`、取得確認時刻、最後の成功時刻を記録。失敗時は直近の数値を維持し、全体 `updated` を最新と偽らない。取得候補と失敗を含む鮮度情報は検証して反映し、workflowの警告と結果欄に要確認箇所を残す（全件取得失敗は失敗扱い）。
- 通常と形態別の数値を分離。各形態に `wikiPage` が確認できた場合に同じ取得器で取得し、未確認なら `formStats` を未確認と表示。通常数値を進化・ヒーローの値としてコピーしない。
- 差分式の `apply-balance.js` は元JSONのSHA256 (`meta.baseHash`)、発効日、対象カード・形態・全フィールドを確認。未対応項目・一部欠損があれば出力を作らず、適用済み印も付けない。同じパッチは再適用しない。過去の `balanceOutOfScope` は未解消の履歴として残す。通常は日次の現在値再取得を使い、古い比率パッチを再取得後の値へ重ねない。
- 画像が取得できない場合、サイトは同じ形態の代替ホストを一度試し、名前付きの独自確認中画像を表示する。別形態への置換・非表示はしない。ランキング画像は全カードの検証に失敗したら503を返し、不完全な画像を正常キャッシュへ入れない。

## 2026-09-23の確認と残件

123カード、通常123・限界突破42・ヒーロー17の182画像を検証。ガーゴイルジャイアントのWikiページは本文が `Coming soon...` のため詳細数値を取得できない。取得対象には含めて毎日再試行し、未取得と表示する。既存の形態別数値59件は検証済み出典の指定待ちであり、取得済みとは扱わない。Wikiの更新遅延や将来の全く新しい仕組みを自動で正解にできると約束するものではない。

テストは新カードの各利用先への反映、形態追加、同URL画像変更、未知形態の検出、名称変更、失敗時の保持、バランスの部分適用防止を含む。Worker側は更新競合・最後の正常版保持・不正manifest・画像完全性を検証する。

未知カード・未対応の進化段階を含む取得試合は、`private/raw/unmapped-card-battles-v1/part-N/` に元API観測を保存する。250件単位のディスク分割は通信・メモリの単位であり、総保存数の上限ではない。台帳対応前の試合を通常カードへ推測変換しない。保存した未解釈観測の自動再集計はこの更新経路には含まず、新しい仕組みの解釈を確認した後にPRIVATE分析側から再開する。

公式 /cards の maxEvolutionLevel=3 は2026-09-23実測で進化・ヒーロー双方のアイコンを持つ4カードに現れるため、その組合せは許可する。試合内の evolutionLevel と同じ意味だと推測せず、未対応の試合内値は原観測を保存する。

## 2026-09-29 環境シェアの分類漏れを解消

画像台帳には存在するガーゴイルジャイアントが、別々に保持された勝ち筋一覧5か所から漏れていた。環境シェアの「その他」をカード名として画像検索していたため確認中画像になっていた。

- 全123カードに `winConditionPriority` を必須化。勝ち筋でないカードも明示的にnullとする。未分類・優先順重複は公開検査で止める。
- 収集・人気デッキ・マイページ・診断・Workerは同じ台帳から37種類の勝ち筋を取得する。新カードを台帳1か所へ追加すると分類にも反映する。
- 「その他」はカードではなく分類用の独自SVGで表示する。既知でない本物のカードは従来の名前付き確認中表示を維持する。
- 過去の「その他」を丸ごと改名せず、通常のcollectorで保存済みの期間内全デッキ署名から再集計する。複数勝ち筋の重複計数・形態は維持する。

## 公式発表と取得値の照合（2026-09-29先行検査）

Wikiの毎日取得が成功しても、公式調整より古い値が戻ることを実測した。`freshness` は取得の状態として残し、別の `balanceVerification` でゲーム調整との照合結果を持つ。

- `catalogue/balance-checks.json` に、確認したSupercell公式発表のURL・本文の指紋・発効日・形態・レベル・対象項目・変更後の値を持つ。現時点では2026-09-08/16発効の28項目。
- 日次取得で最大レベルに加えレベル別の原表を保持。同じ形態・同じレベルの値で比較し、`matched/mismatch/unverified` を区別。数値は自動で比率補正しない。
- 公式ニュース一覧の最新バランス記事と、確認済み記事本文の変更を日次確認。未確認記事・本文更新・通信失敗では最新確認済みと扱わず、ワークフロー結果へ要確認を残す。新しい発表の意味解釈や数値の採用はレビューが必要。
- カード詳細ページに公式変更後の値と照合状態を表示する。最大レベルの取得値と公式Lv11の値を混同しない。通常値をヒーロー／限界突破へ流用しない。
- この検査は対象発表との照合であり、全過去バランスの完全性を保証しない。Wikiの更新遅延、未掲載の新カード・形態は未解消として残す。
- 手動 `quiet_verification=true` はサイト/R2の本番更新だけを検証し、通知・監修シート同期を行わない。自動修理は従来どおり手動build-card-statsを除外する。

## 公式調整の実反映と継続更新（2026-09-29追記）

本人の追加指定：「実際にバランス調整も最新に追従させて」「バランス調整に追従して更新できるようにもして」。照合だけでなく `official-balances.cjs` が発効済みの絶対値を反映する。

1. 毎日13:40 JSTの既存GitHub Actionsで公式ニュースを読む。新しい最終版の記事を取得し、カード台帳の英名と形態、本文の日付・レベル・数値項目を対応付ける。URLの年は使わない（実際に2026年の記事のURLが2027になっている）。予告/WIP・将来日付の変更は適用しない。
2. 最新値をR2の `balanceLedger` に持ち越す。古い記事が新しい変更を戻さないよう発効日を比較する。Wikiを取得した**後**に公式の絶対値を反映し、二重加算・古いWikiへの巻き戻りを防ぐ。元の取得値、公式URL、本文指紋、発効日を項目単位で残す。
3. 実数値の表示・呪文圏内・DPS比較は全カード共通の `combat.level=11` / `combat.stats,hp,dps` を使う。公式Lv11からLv16を推測しない。調整対象の古い最大レベル値は `s16/stats/hp16/dps16` から除外する。未変更の最大レベル値は互換用に保持するが、新しい数値比較には使わない。分類閾値のみ旧Lv16基準に対応するLv11の目安へ変更。
4. 攻撃力・攻撃間隔から単純攻撃のDPSを再計算。複数弾・段階制・空中/地上など単純でない攻撃は、成分対応を推測しない。未対応の新項目・カード名・日付・レベル・攻撃構造は `balanceLedger.pending`、Actions警告、ページの確認待ち表示へ残す。取得障害時は確認済みの変更を維持し、最新確認成功と扱わない。
5. ガーゴイルジャイアントは `catalogue/stat-supplements.json` の出典付きLv11初期資料で体力・属性を補完。攻撃力は9/16公式調整の168で上書き。ファーネスが召喚するファイアスピリットの範囲ダメージも同じ更新へ連動。通常形態の全数値を進化/ヒーローへ一括コピーしない。特殊形態は公式で確認した個別項目を表示する。
6. 全123カード・カードページ123枚・17言語の診断を同じ候補から更新。監修シートにもHP11/DPS11など6列を日次同期するコードを追加（今回の手動検証ではシート送信を省略）。旧GASは参考資料で本番ロジックではない。

現行記事の27種類の独立変更（地上/空中の共有攻撃力は1項目）に、ファーネスへの共有値反映1項目を加えた28項目を対象とする。すべての過去調整や形態の全能力値を検証した意味ではない。非数値の新能力は対応の実装・確認が必要で、Codexが常駐して自動修理する仕組みではない。

検証：`node --test tools/test-card-catalogue.mjs tools/test-balance-verification.mjs tools/test-official-balances.mjs`。実記事の構造、新記事への追従、将来日の除外、Wikiの古い値、二重実行、障害、DPS、同レベルの呪文比較、召喚ユニット、形態分離を含む。
