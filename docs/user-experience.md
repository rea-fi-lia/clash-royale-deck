# 操作状態・初回ガイド・マイページ

2026-09-22。デスクトップ改修後の利用者向け改善。

## 戻る・進む

`js/builder.js` はページを離れる際に `history.state.crdbBuilder` を保存する。URL、デッキ8枠、選択SLOT、読込時署名、アカウント、検索、タイプ/コスト絞り込み、並び順、アシスト、PCの固定、スクロール位置が対象。同じ履歴項目への復帰/再読込にだけ適用し、別の共有URLや別タブには流用しない。空デッキも復元できる。保存デッキの内容をクラウドへ書き戻す操作ではない。

SLOT番号はアカウント変更時に解除する。通常のデッキ復帰は従来の `cr_workdeck` も維持。モバイルの画面構成は変更せず、従来のスクロール領域を復元する。

## チュートリアル

新PC UIを対象に、SLOT・デッキ固定・アシストの3項目をスポットライト表示。`js/tutorial.js` の `TUTORIAL_STEPS` が登録表。日本語/英語の説明を持ち、他言語では英語を使用する。ガイドの再生入口は17言語へ翻訳。

- 項目IDは意味と版を持つ。現在は `desktop_slots_v1`、`desktop_pin_v1`、`desktop_assist_v1`。
- 追加は新しいIDを追記。既存項目の再説明が必要なら新しい版のIDにする。既存IDを別の意味で再利用しない。
- Firestoreの既存の本人専用ドキュメント `users/{uid}.tutorialProgress.{stepId}` に `shownAt`（実表示）、`completedAt`（次へ/完了）、`skippedAt`（残りを省略）をUnixミリ秒で保存。省略した項目を表示済みとは偽らない。
- 管理者はFirestoreの当該利用者ドキュメントで各項目の進捗を確認できる。管理APIの利用者横断集計はGoogleの読み取り認証接続待ちであり、今回集計画面まで接続済みとは扱わない。
- `cr_tutorial_v1:account:{uid}` は本人の端末キャッシュ兼再送待ち、`cr_tutorial_v1:guest` は未ログインの履歴。初回ログイン時にゲスト履歴を一度だけ統合し、その後別アカウントへ再利用しない。
- 表示・完了・スキップいずれかがある項目は自動再生しない。途中で離れた場合も、次回は未表示項目から案内。使い方ガイドから任意に再生できる。
- 既知のログイン状態はプロフィール読込を待つ。Firestore失敗でも端末履歴を保持し、次回来訪/オンライン復帰で再送。認証が変わっても書込先UIDを途中で差し替えない。
- 未ログインの別端末、ストレージ削除、プライベートブラウズをまたいだ同一人物判定はできない。ログインするとアカウント単位で共有する。追加Cookieや追跡用IDは作らない。

Firestoreルールの権限拡張は不要。既存の本人プロフィール更新権限を利用し、課金情報の保護は維持する。記録の時刻はクライアント時刻で、監査や課金判定には使用しない。

## タグ・マイページ

`js/experience-core.mjs` の共通処理をアカウントメニューとマイページの2入力欄で使用。`#`は表示側で付ける。全角/半角英数字をNFKCで正規化し、大文字A–Zと数字0–9だけにする。IME変換中は入力を消さず、確定後に正規化する。日本語かなからタグを推測変換はしない。

マイページは認証モジュールを明示的に読み込み、登録済み `profile.crTag` を自動表示する。手動登録時はログイン中ならアカウントにも保存。取得中に別タグを選んだ場合は古い応答を破棄する。

新しく開く/タグを切り替える時は記録がある最短期間（1日→1週間→1ヶ月→1年）を選ぶ。開いている間に自分で選んだ期間はデータがあれば維持する。1年以上前にしか記録がない場合は「全期間」。空の期間は選択不可。履歴自体は削除しない。

勝率・勝敗・平均クラウン差はヘッダー右側の3グループへ。12個のクラウン内訳ボックスは削除。「あなたの戦績」は期間の記録数・勝敗バー・トロフィー推移として残す。チャートは画面幅で縮尺を組み直し、長い記録間隔/大幅なリセットらしき箇所を線でつながない。

### トロフィー効率の定義

既存APIの `tr` は試合**前**のトロフィーで、確定した試合別増減は保存されていない。そのため「推定」と明記し、獲得量 ÷（獲得量＋減少量）を表示。隣接する記録が30分以内、両方正のトロフィー、変動が±60以内、前試合の勝敗と方向が整合する区間のみ使用する。欠損値は飛び越えない。サンプル区間数・獲得・減少・純増を併記し、計算不能は0%でなく「—」。未収集試合を含む可能性は残る。最新試合の終了後増減は含めない。正確な1戦ごとの効率が必要なら別途APIに実増減を保存する。
