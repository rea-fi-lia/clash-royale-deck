## 2026-08-11 の障害：収集が3時間26分止まった

```
08/11 18:34 JST  ✅ 最後の正常
08/11 18:44 JST  ❌ … 11回連続で失敗 …
08/11 21:48 JST  ❌
08/11 22:01 JST  ✅ 復旧
```

**原因**：帯別イベントの保持上限を 800→2400 へ引き上げた副作用。
`(旧22万件).concat(今回分)` で巨大な中間配列を作ってから `filter → sort` していたため、
保持107,372件／候補219,202件の絞り込み中に **JavaScript heap out of memory（exit 134）**。

**直した3点**
1. `concat` をやめ、1本の配列へ push しながら**その場で期限切れを捨てる**（中間配列を作らない）。旧配列の参照も明示的に手放す
2. `NODE_OPTIONS=--max-old-space-size=8192`（GitHubランナーは16GB）
3. 上限を現実的な値へ：**帯 2400→1600 ／ 全体 120000→80000**（47帯×1600＝75,200。頭打ちだった800の倍で、メモリにも収まる）

**実害**
- 全体統計：**軽微**。毎回ちがうプレイヤーを標本として拾う方式なので、止まった分は「その3時間に拾えたはずの標本が減った」だけ。既存データは壊れていない。3日窓なので数時間で厚みは戻る
- 個人データ（先駆けタグ）：**ゼロ**。joの最終試合は8/3で、停止時間帯にプレイしていなかった。ただし3時間26分は**75分ルールを超えている**ので、プレイしていたら取りこぼしていた

### 通知の仕組み（`tools/notify.js` ＋ `collect.yml`）
- **2回連続で失敗したときだけ**鳴らす（1回の瞬断では鳴らさない）
- **復旧したときも1回**知らせる
- 送り先は環境変数があるものだけ。**無ければ黙ってスキップ**＝設定した瞬間から動き出す

| 送り先 | 必要なSecret |
|---|---|
| LINE（Messaging API push） | `LINE_PUSH_TOKEN`（チャネルアクセストークン）／`LINE_PUSH_TO`（送信先userId） |
| Slack | `SLACK_WEBHOOK_URL`（Incoming Webhook） |

### ⚠️ 園の公式LINEは使わない

LINEで受け取るなら **ReA名義のLINE公式アカウントを別に作る**（joの作業）。

**joがやること（LINEで受けたい場合）**

## 上限を触るときの心得

収集の枠（シード数・保持件数）は**メモリと直結**している。上げるときは：
1. まず1段だけ上げて、**次のrunのログで `保持 X/Y` と実行時間を見る**
2. `Y`（候補件数）が20万を超えるなら、絞り込みの実装がメモリを食っていないか疑う
3. `rate-limit 429hits=` は別問題（APIの制限）。**429が0でもメモリで落ちる**ことがある ← 今回これ
