# 多言語化（17言語）の仕組み

2026-10-12 作成（Claude）。本人の依頼「まだ翻訳できてないページも今後増設したページも翻訳対象になって翻訳がつくように設計反映しておいて」。

## 一言で

**日本語のページとコードが正本。訳す対象は道具が自動で集め、無い訳だけを AI が足す。訳が無い間は英語で出す（日本語は出さない）。**

## 訳の置き場所（上ほど優先）

| 置き場所 | 中身 | 誰が書くか |
|---|---|---|
| `i18n.js` の `DICT` | 人が書いた画面の文の訳 | 人（直したい訳を固定するときもここ） |
| `tools/i18n-content/<lang>.json` | ページの本文の訳（`gen-i18n` が言語ページへ静的に焼き込む） | 機械訳＋人の手直し |
| `tools/i18n-runtime/<lang>.json` | 画面の文（JS が後から出す文）の機械訳 | `tools/i18n-translate.js` |
| `js/i18n/<lang>.js` | 上の json から作る読み込み用のファイル（手で直さない） | `tools/i18n-translate.js` |

`i18n.js` の `tr()` は「その言語の訳 → 英語 → 日本語」の順に探す。機械訳（`js/i18n/<lang>.js`）は、人の訳が無い所にだけ足される。

## 訳す対象を自動で集める（`tools/i18n-lib.cjs`）

- **ページ**：ルートにある `.html` を全部。外すのは `admin.html`・`3d.html`・`google*.html` と、`<meta name="crdb-i18n" content="off">` を書いたページ。**新しいページを足せば、言語ページ・訳の対象・サイトマップに自動で入る**
- **本文**：ページの日本語のテキスト（`gen-i18n` と同じ区切り）と、説明文などの meta。`<!--JA-ONLY-->…<!--/JA-ONLY-->` で囲んだ所は日本語のページだけに出る
- **画面の文**：JS の翻訳関数に渡した日本語。`_tr('…')`・`_tf('…{n}…', {n})`・`TR`・`TRF`・`TRX`・`T`・`tr`・`tx`・`CRI18N.tr`・`CRI18N.t`、印の `LBL('…')`（builder.js）・`L('…')`（tools/build-static-content.js）。ほかにページの属性（title・placeholder・aria-label・alt）とカードの役割
- 日本語のページが noindex（マイページ）なら、言語ページも noindex にしてサイトマップに入れない

## 新しく文やページを足すとき

1. 画面に出す日本語は、**文ごと**翻訳の関数に通す。数字や名前が入る文は `{n}` を入れた文ごと（`TRF('{n}枚目を伸ばす方向', { n })`）。語順が変わるので、切れ端をつなげない
2. 三項演算子は中の文を1つずつ通す（`cond ? TR('A') : TR('B')`）。`TR(cond ? 'A' : 'B')` は道具が文を見つけられない
3. 判定にも使う日本語のラベルは、元では `LBL('…')`（値は日本語のまま）、表示する所で `TR()`／`TRX()`
4. 自由に組み立てた文（アシストの理由など）は表示する所で `TRX()`。訳が無ければ日本語以外のページでは出さない
5. Mac Studio で訳を足して、言語ページを作り直す：

```bash
node tools/i18n-translate.js --fill --engine gemini-local --model gemini-3.8-flash --langs en
node tools/i18n-translate.js --fill --engine gemini-local --model gemini-3.5-flash-lite
node tools/gen-i18n.js
```

- 数えるだけ：`node tools/i18n-translate.js`
- 英語を先に作る（ほかの言語は日本語と英語の両方を見せて訳させる）。英語は他の言語の手本なので、出来を目で確かめて `tools/i18n-runtime/en.json` を直す
- 検査 `tools/check-card-images.js` の [1h] が「英語の訳が無い文」を赤にする。ほかの言語は件数だけ出す（無い分は英語で出るので、赤にしない）

### APIが利用できないとき（2026-10-24更新）

- HTTP 429 は保存済みの訳を保持して全バッチを停止する。Fuguはタイムアウトなどの失敗も自動再試行せず停止する。別モデルや従量課金への自動切替はしない。
- `--max-batches` は失敗と再試行を含めた呼び出し上限。途中の結果は各バッチの成功時に保存される。
- 続行する場合は公開原稿の日本語・確認済み英語と既存画面名を照合して不足分を手動補完できる。既存訳を保持し、数値・条件・差し込み・HTMLを検査してから `--write-js` と `gen-i18n.js` を実行する。
- 頁本文の変更とタイトル・descriptionの翻訳を一緒に確認する。古い固定SEO文がある場合は、現在の日本語本文から訳す仕組みに合わせる。

## 訳の確かめ（`tools/i18n-translate.js` が自動で捨てる訳）

差し込み `{…}` の違い・HTML のタグの違い・数字の違い（1と2は数えない）・元に無い絵文字・日本語のかなの残り（中国語は漢字を許す）・その言語の文字が無い（ロシア語・韓国語・中国語・アラビア語・ペルシャ語・タイ語）・長すぎる。捨てた文は次の実行でまた試す。

用語は道具の中の用語集（進化・ヒーロー・チャンピオン・デッキ）と、このサイトの既存の訳から拾った例にそろえる。2026-10-12 の試験で「ヒーロー」がトルコ語・スペイン語でチャンピオンと訳されたため。

## AI と送ってよいもの

- 送るのは**公開しているサイトの文だけ**（利用者の入力・戦績・鍵は送らない）
- Mac Studio：`gemini-local`（Gemini の無料枠・1分15回・1日500回）か `fugu-local`（Fugu の定額のキー）
- GitHub の自動処理（`.github/workflows/i18n-fill.yml`）：リポジトリの変数 `I18N_FILL_ENGINE`（`gemini-api` か `fugu-api`）を入れたときだけ訳を足す。入れていない間は数えるだけ。鍵は Secrets の `GEMINI_API_KEY`（請求を設定していないプロジェクトの無料枠のキー）か `SAKANA_API_KEY`（**定額か従量かは未確認**・定額と確かめてから選ぶ）。pull_request では動かさない

## 言語の決め方（`i18n.js`・2026-10-12 から）

- 言語ページ（`/en/` など）はその言語。来たことをこの訪問の間だけ覚える（カードページなど言語ページの無い所でも同じ言語で出す）
- 日本語のページ（ルート・カードページ）は、**利用者が選んだ時だけ**別の言語にする（`?lang=`・言語の選択欄・言語ページから来た）。ブラウザの言語だけでは変えず、右上に小さな案内を出す
  - 前は英語のブラウザで開くと日本語のページの上から画面の文だけ英語になり、`<html lang>` も en になっていた。Google の描画も英語のブラウザとして動くので、日本語のページが英語まじりに見えていた可能性がある（推測）
- 選んだ言語のページがあれば、その言語のページへ移る（本文まで訳してある）。無ければ（カードページ）その場で画面の文を訳す。機械訳は `js/i18n/<lang>.js` をその時に読む

## 人気デッキの「今日の環境のまとめ」

`tools/build-static-content.js` が毎日、日本語の欄と17言語の版（`tools/static-content/decks-summary.json`）を書く。文は `L()`／`LF()` で訳を引き、どれかの文に英語の訳も無い言語は書き出さない（その言語のページでは欄ごと外れる）。カード名は英語の公式名。

## まだやっていないこと

- カード個別ページ（`/cards/*.html`）の言語版：日本語だけ。AdSense の審査に通るまでは機械翻訳のページを増やさない（審査で「自動生成の割合」を見られるため）。作るときは `build-card-pages.js` の出力を `i18n-lib` の対象に足せば、同じ道具で訳せる
- 人の目での見直し：アクセスの多い英語・トルコ語・スペイン語・ロシア語から
