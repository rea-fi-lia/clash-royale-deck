## 帯の定義（47帯）

**トロフィー（トロフィーロード）0〜14,099 を 300 刻み**で切った 47 個。

```
0-299, 300-599, 600-899, …, 13500-13799, 13800-14099
```

- あなたの帯 ＝ 直近試合の開始時トロフィー。表示は ±150 の近い帯も見る
- ランク戦（PoL）はトロフィーと別軸なので混ぜず、別集計（上位1000ランカー）

## 「全試合」は誰にも取れない（構造的事実）

- **試合を列挙する API はこの世に存在しない**。試合は必ずプレイヤー経由（`/players/{tag}/battlelog`＝直近25戦）でしか取れない。「アリーナXの今日の全試合」という口は無い
- したがって全数を持つのは Supercell だけ。**RoyaleAPI も観測ベースの標本**（彼らが巡回したタグの分だけ。規模が大きいだけで構造は同じ）
- 現実解は二本立て：
  1. **全体** … 発見と巡回を広げて標本を厚くする（このファイルの主題）
  2. **登録した個人** … 毎時取得すれば**漏れゼロを保証できる**（25戦×最短3分=75分 ＞ 60分。→ `docs/monetization.md`）

## 飽和の判定方法（「取り切った」をどう知るか）

毎時のログに出る `clan-crawl newPlayers=N` を見る。

- N が数千 → まだ広げる（現在ここ。3,707人/時）
- N が数百 → 巡回国・クラン数をもう一段増やして様子見
- N がほぼ0 → **この入口から見える範囲は取り切った**

ただし「入口から見える範囲」＝クランに所属しランキングに載る層＋その対戦相手。クラン未所属で誰の対戦相手にもならないプレイヤーは構造上見えない（これはどのサービスでも同じ）。

## 安全弁

- 429 が出ればログの `rate-limit 429hits=` に必ず出る。増え始めたら拡大を止めて見直す
- 収集は毎時2重トリガ（Worker cron :15 ＋ Actions :37/:57）で freshness gate が重複を防ぐ

### Exact template observations (2026-09-22)

既存の上位プレイヤー収集に `ranked-deck-observations-v1` の非公開R2生記録を追加する。各収集時点で対象プレイヤーの最新ランク戦で使った8枚・形態を保持。追加のゲームAPI呼出しは不要。日別順位/継続判定の分析本体は非公開側で行う。既存の月次合計から過去の連続日数は復元しない。旧cardhistの署名は特殊形態の種類まで区別しない場合があるため、新記録の形態判定へ流用しない。

## 上流が止まったとき（2026-10-03）

ゲームAPIへの入口は2つある。実装は `tools/cr-upstream.cjs` の1か所だけ。

| 入口 | 使うとき | 鍵 |
|---|---|---|
| RoyaleAPI の中継 `proxy.royaleapi.dev` | **ふだん** | `CR_TOKEN`（許可IP＝中継の 45.79.218.79） |
| Supercell 公式 `api.clashroyale.com` | 中継が死んでいて、Secrets に `CR_DEV_EMAIL` / `CR_DEV_PASSWORD` があるときだけ | 実行のたびに開発者ポータルで「その実行機のIP用の鍵」を作る（名前 `crdb-actions-…`） |

中継は第三者の無償サービスで、実際に止まっている（8/5・10/1・10/3。10/3 は成功率20%が5時間以上続き、毎時の収集が全部止まった）。

```mermaid
flowchart LR
  P["健康診断<br/>軽い要求を最大6回・3回成功で合格<br/>落ちたら20秒後に1回だけ測り直す"] -->|合格| C["いつもどおり中継で収集"]
  P -->|不合格| K{"CR_DEV_* が<br/>登録されている？"}
  K -->|はい| O["公式へ切り替え<br/>このIP用の鍵を作って収集"]
  K -->|いいえ| D["UPSTREAM_DOWN<br/>数秒で降りる・何も書かない"]
  C -->|"途中で5xx・通信失敗が<br/>6割以上・1分以上続く"| K
  M["Supercellのメンテ<br/>503 inMaintenance"] --> D
```

- **降りた回の扱い**：終了コード75。しおり（lastT 等）は進めず、取れた分の原本だけ保存する。自動修理（auto-repair）は `UPSTREAM_DOWN` を見て AI を起こさない。通知は「上流が停止中・コードは正常」と書き、鳴らし始めた後は6回に1回へ間引く（復旧の知らせは必ず鳴る）
- **一瞬の揺れでは止めない**：1チャンク40件が全部落ちる程度では止めず、「6割以上が失敗」が「1分以上」続いたときだけ止める
- **メンテは切り替えない**：Supercell のメンテ中は公式も同じなので、すぐ降りる
- **公式への切り替えを有効にする**：リポジトリの Secrets に `CR_DEV_EMAIL` と `CR_DEV_PASSWORD`（developer.clashroyale.com のログイン情報）を登録するだけ。**本番の実行（main→data）にだけ渡り**、AIが書いた修正ブランチの検証実行には渡らない。試運転は Actions → collect decks → Run workflow で `upstream=official`
- **消す鍵は自分が作った `crdb-actions-…` だけ**。本人の鍵には触らない。10個の枠が本人の鍵で埋まっていたら、切り替えずに止まって理由を知らせる
- **検証実行の隔離**：main→data 以外の収集（自動修理の検証など）は、R2 の置き場を `verify/`・書き込み先ブランチを `data-test` に分ける。以前は R2 だけ本番と同じ `private/` に書く作りで、「本番を汚さない検証」になっていなかった
- **取り戻せないもの**：止まっている間に25戦を超えて進んだ試合は戻らない（APIが直近25戦しか返さない）

同じ入口を使う所：収集（`tools/collect.js`）／カード台帳の更新（`tools/update-card-catalogue.js`。上流停止なら公式一覧の取り直しだけ省いて続行）／カード画像の点検（`tools/check-card-images.js`。[2]の突合を省略）。
Worker の `/api/me/sync`・`/battlelog` は中継の直書きのまま（中継が死ぬと保存済みデータを返して「同期できず」と印を付ける）。Worker は出口のIPを固定できないので、IP指定の鍵を作るこの方式はそのままでは使えない。
